# WordPress → Telegram: الإعداد والاختبار

هذا القالب يقرأ مقالاً منشوراً ويرسل عنوانه ورابطه. لا ينشئ مقالات ولا ينشر مسودات. لا يحتاج PowerShell أو cmd.exe؛ الإعداد من واجهة Make.

## الملفات والحسابات

استخدم `wordpress-telegram.make-blueprint.json`، لا ملف وثيقة الخطة JSON. تحتاج موقع WordPress تديره، حساب Make، وبوت Telegram ومحادثة بدأت البوت. لا تتضمن النسخة اتصالات أو توكنات أو Chat ID أو مخزناً من حساب آخر.

1. أنشئ سيناريو جديداً غير مفعل في Make. اختر More → Import blueprint → Choose JSON blueprint، ثم Import blueprint. احفظ بعد إعداد الاتصالات.
2. في WordPress ثبّت Make Connector وفعّله. من Make → General Settings اعرض API Key محلياً، وحدد صلاحيات قراءة المقالات اللازمة فقط. لا تحتاج صلاحيات الإنشاء أو الحذف لهذا المسار.
3. في الوحدة 1 اختر أو أنشئ اتصال WordPress: عنوان REST الأساسي هو `https://YOUR-SITE/wp-json/`، والمفتاح هو مفتاح Make Connector. احتفظ بالحالة `publish` وحد النتيجة إلى `1` أثناء الاختبار.

## بوت Telegram وChat ID

أنشئ البوت عبر `@BotFather` باستخدام `/newbot` إن لم يكن لديك بوت. افتح رابط بوتك واضغط Start. أدخل التوكن في اتصال Telegram Bot داخل Make فقط، ثم اختر هذا الاتصال في الوحدة 4.

للحصول على Chat ID لمحادثة خاصة مع بوت اختبار جديد لا يستخدم webhook: أرسل رسالة للبوت، ثم استخدم وحدة Telegram Bot → Get Chats أو Get Updates في سيناريو مؤقت وافحص `chat.id` للمحادثة المقصودة. لا تستخدم مسار الاستعلام هذا مع بوت مرتبط بـWatch Updates/webhook؛ لا تفصل webhook إنتاج لتجربة الدليل. للقناة العامة، يذكر توثيق Make استخدام `@channelusername` مع صلاحيات البوت المناسبة. راجع [توثيق Telegram في Make](https://apps.make.com/telegram) لحالتك.

ضع المعرف في Chat ID بالوحدة 4. احتفظ بالنص المربوط بعنوان المقال ورابطه، واترك Parse mode فارغاً. في تجربة محدودة يمكن إضافة سطر «اختبار» إلى النص ثم إزالته قبل الاستخدام العادي.

## مخزن الإيصالات

أنشئ Data store مخصصاً لهذا السيناريو والموقع. اجعل البنية تحتوي `state` و`destination_id` من نوع Text و`updated_at` من نوع Date. Key مدمج في Make وليس عموداً إضافياً. اختر المخزن نفسه في الوحدات 2 و3 و5.

- الوحدة 2 تفحص المفتاح `wp:{{1.id}}`.
- الوحدة 3 تحجزه بحالة `pending`، مع Overwrite معطلاً.
- الوحدة 5 تحفظ `sent` ومعرف رسالة Telegram، مع Insert missing record معطلاً.
- اترك فلتر `{{2.exist}}` كما هو وSequential processing مفعلاً.

إذا كانت مساحة المخازن موزعة بالكامل، حل القيد أولاً. لا تعدل مخزن إنتاج أو تمسح سجلاته لمتابعة الشرح. استخدام مخزن موجود بمفاتيح اختبار منفصلة يحتاج معرفة بنيته وإذن مالكه؛ لا تمنحك الحزمة ذلك الإذن.

## اختبار واحد ثم اختبار التكرار

1. من قائمة الوحدة 1 اختر Choose where to start → Choose manually، وحدد مقالاً منشوراً واحداً، ثم Save. أبقِ limit=1 والسيناريو Inactive.
2. نفّذ Run once. تحقق من نجاح الوحدات الخمس، وصحة عنوان الرسالة ورابطها في Telegram، ووجود `state=sent` و`destination_id` في السجل.
3. أعد اختيار المقال نفسه من نقطة البدء ثم Run once. يجب أن ترى ناتج الوحدة 2 `exist=true` وأن يتوقف المسار قبل الحجز والإرسال؛ لا تكفي عبارة «لا توجد عناصر جديدة» لإثبات اختبار التكرار.
4. قبل التفعيل اختر From now on إذا لم تكن تريد الأرشيف، واضبط الفترة والمنطقة الزمنية داخل Make، ثم Save. الوقت المختار في مخطط TechMouad لا يفعّل جدولة Make.

إذا بقي سجل `pending` بعد مهلة، افحص Telegram وسجل التشغيل قبل إعادة المحاولة؛ قد تكون الرسالة وصلت. لا تتجاوز الحجز بمعالج خطأ يسمح بالإرسال. هذا تصميم لتقليل التكرار، وليس ضمان exactly-once لجميع الأعطال.

الاختبار المتصل يستخدم اتصالات يختارها صاحب الحساب؛ استيراد JSON وحده لا يمنح البوت أو WordPress صلاحية إضافية. المصادر: [WordPress](https://apps.make.com/wordpress)، [Blueprints](https://help.make.com/blueprints)، [Data stores](https://help.make.com/l6du-data-stores).
